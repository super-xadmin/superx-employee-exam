# การทำงานและขอบเขตของรุ่นเริ่มต้น

## เส้นทางข้อมูล

เบราว์เซอร์ → Cloudflare Worker API → D1

D1 เก็บพนักงาน ชุดข้อสอบ สำเนาข้อสอบตอนเริ่มสอบ คำตอบ ผลประเมิน ประวัติ และคิว Lark เมื่อเปลี่ยนสถานะผลสอบ SQL trigger สร้างรายการแจ้งผลใน transaction เดียวกัน จากนั้น Worker ส่งไป Lark ทันทีเท่าที่ทำได้ และ Cron ช่วยประมวลผลซ้ำทุก 5 นาที

ไฟล์ `public/` มีเฉพาะหน้าเว็บ ไฟล์เฉลยใน `src/seed.js` ไม่อยู่ในชุด static assets API พนักงานตัดเฉลย rubric และคำวิเคราะห์สำหรับผู้ประเมินออก ผู้สอบดูคำแนะนำที่ผู้ประเมินยืนยันแล้วได้หลังสรุปผล

## สถานะการสอบ

`in_progress` → `pending_review` → `passed` หรือ `failed`

ถ้ามีแต่ข้อเลือกตอบ จะข้าม `pending_review` ได้ คะแนนข้อเลือกตอบคำนวณจากเฉลยฝั่งเซิร์ฟเวอร์เท่านั้น ข้อเขียนไม่ให้คะแนนจากจำนวนคำสำคัญหรือ AI

- ผ่านเมื่อ `คะแนนที่ได้ / คะแนนเต็ม × 100 >= 95` ใช้ค่าจริงก่อนแสดงผล เปอร์เซ็นต์แสดงทศนิยม 2 ตำแหน่งโดยไม่ปัดขึ้นข้ามเกณฑ์
- ผลครั้งแรกเป็น `failed` เท่านั้นที่เริ่มครั้งที่ 2 ได้
- ขณะ `pending_review` หรือเมื่อ `passed` ไม่ให้เริ่มซ้ำ
- ตาราง attempts มี constraint จำกัด attempt_no เป็น 1/2 และ unique พนักงาน + ชุดข้อสอบ + ครั้งที่
- รหัสใหม่หรือออกจากระบบไม่ล้างประวัติการใช้สิทธิ์
- ชุดข้อสอบใหม่เป็นการประเมินใหม่ มีสิทธิ์แยกจากชุดเดิม ไม่มีการรีเซ็ตสิทธิ์รายบุคคลในหน้าเว็บ
- ใช้ snapshot เก็บโจทย์ เฉลย เวลา และเกณฑ์ ณ ตอนเริ่มสอบ ปิดรับข้อสอบไม่หยุดผู้ที่เริ่มทำแล้ว

## บันทึกคำตอบและหมดเวลา

หน้าเว็บบันทึกหลังหยุดพิมพ์ประมาณ 700 มิลลิวินาที พร้อมแสดงผลการบันทึก ไม่มีการอ้างว่าบันทึกสำเร็จหากเซิร์ฟเวอร์ไม่ตอบรับ ไม่เก็บคำตอบใน localStorage เพื่อไม่ทิ้งข้อมูลของผู้สอบคนก่อนในเครื่องส่วนกลาง

API ใช้ revision ตรวจคำขอเก่าเพื่อไม่ให้หลายหน้าต่างเขียนทับกัน หากขัดแย้งจะให้โหลดหน้าใหม่ เมื่อครบเวลาคำตอบใหม่ที่มาถึงหลัง deadline จะถูกทิ้ง ใช้เฉพาะคำตอบที่เซิร์ฟเวอร์บันทึกไว้แล้ว

Cron สรุปรายการหมดเวลาได้รอบละ 50 รายการ การเปิดรายการสอบหรือหน้าข้อสอบยังเรียกตรวจหมดเวลาด้วย ระบบนับเวลาจาก deadline เซิร์ฟเวอร์ การเปลี่ยนนาฬิกาเครื่องไม่เพิ่มสิทธิ์เวลาสอบ หากเน็ตขาดช่วงหมดเวลา คำตอบที่ยังบันทึกไม่สำเร็จจะไม่รวมในคะแนน

## การเข้าสู่ระบบและการเข้าถึง

รองรับเฉพาะ Email OTP และ Lark OAuth ทั้งผู้ประเมินและพนักงานใช้หน้าเดียวกัน ระดับสิทธิ์กำหนดฝั่งเซิร์ฟเวอร์หลังยืนยันตัวตน:

- ผู้ประเมิน: อีเมลต้องอยู่ใน `ADMIN_EMAILS` ค่าเริ่มต้น `phop@super-x.tech` การนำออกจากรายชื่อยกเลิกสิทธิ์เซสชันเดิมทันที
- พนักงาน: อีเมลต้องอยู่ใน employees และ active=1 เก็บชื่อ ฝ่าย และ auth_version สำหรับตรวจทุกคำขอ
- OTP สุ่ม 6 หลัก ใช้ 10 นาทีครั้งเดียว เก็บเฉพาะ hash ที่ผูกกับ SESSION_SECRET และ browser challenge พิสูจน์ว่าผู้ใช้เข้าถึงกล่องอีเมลได้
- Cookie ของ email challenge เป็น HttpOnly และ SameSite=Strict จำกัด path เฉพาะ email auth
- จำกัด OTP ผิด 5 ครั้งและจำกัดการขอรหัสต่ออีเมลและ IP ใช้ atomic UPDATE ป้องกันยืนยันพร้อมกันซ้ำ
- Lark ใช้ authorization-code flow ของ confidential client แลก token ฝั่งเซิร์ฟเวอร์ ตรวจ tenant key แล้วเทียบ open_id กับการผูกบัญชีที่ผู้ดูแลตั้งไว้ ไม่ใช้ email ใน user_info เพื่อให้สิทธิ์โดยอัตโนมัติ
- State ของ OAuth เป็นค่าสุ่ม ใช้ครั้งเดียว มีวันหมดอายุ และผูก browser cookie แบบ HttpOnly/SameSite=Lax เพื่อรับ callback ข้ามไซต์ พร้อม PKCE แบบ S256
- ไม่เก็บ Lark user access token หลังอ่านข้อมูลผู้ใช้ และไม่ส่ง App Secret/access token ไปหน้าเว็บ
- เซสชัน HMAC cookie เป็น HttpOnly, SameSite=Strict, Secure เมื่อ HTTPS อายุ 8 ชั่วโมง และยอมรับเฉพาะ auth_method email/lark ทำให้เซสชันรุ่นเก่าใช้ไม่ได้
- เปลี่ยนอีเมล/ปิดสิทธิ์จะเพิ่ม auth_version และบันทึกการผูก Lark ที่ผู้ประเมินยืนยัน รหัสพนักงานเป็นเพียงรหัสอ้างอิง ไม่มีรหัสผ่านหรือ access code
- ตรวจ Origin ทุกคำขอเปลี่ยนข้อมูล ยกเว้น OAuth callback เป็น GET และตรวจ state/cookie แทน
- ใช้ prepared statements และ escape ข้อมูลก่อนแสดง HTML

การยืนยันคะแนนและ audit ใช้อีเมลผู้ประเมินจากเซสชัน ไม่รับชื่อผู้ประเมินจากข้อความที่เบราว์เซอร์ส่งมา ผู้ประเมินที่ได้รับอนุญาตยังจัดการได้ทุกฝ่าย ยังไม่มีการแยก role ผู้ประเมินรายฝ่ายหรือการอนุมัติหลายระดับ

## Lark และ AI

คิวส่ง Lark มี snapshot ของแต่ละเหตุการณ์ จึงไม่เปลี่ยนเนื้อหาข้อความรอประเมินให้กลายเป็นข้อความผลสุดท้ายภายหลัง ตรวจทั้ง HTTP response และ `code === 0` ของ Lark ก่อนระบุว่าส่งสำเร็จ ใช้ lease ป้องกันผู้ส่งหลายตัวทำงานซ้อน และลองซ้ำแบบเพิ่มเวลารอ

ผลวิเคราะห์ตามคำสำคัญบอกเพียงว่าพบ/ยังไม่พบคำในคำตอบ ไม่เข้าใจบริบท การปฏิเสธ หรือความหมายทดแทน จึงไม่มีผลต่อคะแนนโดยตรง Workers AI ปิดไว้เริ่มต้นและเรียกเมื่อผู้ประเมินกดเท่านั้น ส่ง prompt ที่บอกให้มองคำตอบเป็นข้อมูล ห้ามทำตามคำสั่งในคำตอบ และบังคับให้ผู้ประเมินตรวจยืนยัน ผล AI อาจยังผิดหรือถูกชักนำได้ จึงไม่ใช้เป็นผลสอบอัตโนมัติ

## การตรวจสอบที่แนบมา

`npm test` ทดสอบตรรกะและ API กับฐานข้อมูล SQLite จริงที่ใช้ schema เดียวกับ D1 ผ่าน adapter ใน tests มี mock เฉพาะบริการภายนอก Resend, Lark และ Workers AI ไม่มีการส่งข้อความจริงจาก test

`npm run build` ใช้ Wrangler จัด bundle แบบ dry run ไม่ deploy และไม่เชื่อมฐานข้อมูลจริง ควรทดสอบการรับข้อความในกลุ่ม Lark, โมเดล AI (ถ้าเปิด), DNS, HTTPS และข้อมูลข้อสอบจริงหลังตั้งบัญชีของคุณแล้ว

หน้าภาพรวมแสดงพนักงาน/ผลสอบล่าสุดไม่เกิน 1,000 รายการ ชุดข้อสอบไม่เกิน 200 ชุด คิวล่าสุด 100 รายการ CSV รวมทุกรายการ เหมาะสำหรับรุ่นเริ่มต้น หากข้อมูลมากควรเพิ่ม pagination และ export แบบแบ่งส่วน

ยังไม่มีการคุมสอบผ่านกล้อง การล็อกเบราว์เซอร์ การจับทุจริต การสุ่มคลังข้อสอบ การส่งข้อความส่วนตัวรายผู้ประเมิน หรือการจัดตารางสอบเป็นรอบ
