# SuperX Academy — ระบบสอบพนักงาน

เว็บภาษาไทยสำหรับ **ฝ่ายเทคนิค / ฝ่ายติดตั้ง / ฝ่ายขาย** พร้อมหน้าเว็บและเซิร์ฟเวอร์ Cloudflare Workers + D1 นำทั้งโฟลเดอร์ขึ้น GitHub ได้

**เข้าสู่ระบบผ่านอีเมลหรือ Lark เท่านั้น** ไม่ใช้รหัสพนักงานเป็นชื่อเข้าใช้ และไม่มีรหัสผ่านผู้ประเมินส่วนกลาง

หน้าตาเวอร์ชันนี้ใช้โทนขาว–ไซแอนของ SuperX พร้อมโลโก้และภาพ RoboVan จาก Company Profile จัดวางแบบเรียบโปร่ง รองรับมือถือ ดู [แนวทางการออกแบบ](docs/DESIGN-TH.md)

**ผู้ดูแลหลัก:** `phop@super-x.tech` (ตั้งไว้ใน `vars.ADMIN_EMAILS`)

**เกณฑ์สอบ:** ผ่านตั้งแต่ **95% ขึ้นไป** สอบซ่อมได้ **1 ครั้ง** รวม 2 ครั้งต่อพนักงานต่อชุดข้อสอบ เปิดสอบซ่อมเมื่อผลครั้งแรกยืนยันว่าไม่ผ่านเท่านั้น

## เริ่มใช้งาน

1. ติดตั้ง Node.js 24 LTS และเปิด Terminal ในโฟลเดอร์นี้
2. ใช้คำสั่ง:

```sh
npm ci
npm run setup:local
npm run db:local
```

3. ตั้งค่าการยืนยันตัวตนอย่างน้อยหนึ่งช่องทางตามหัวข้อถัดไป
4. `npm run dev` แล้วเปิด URL ที่แสดง ปกติคือ `http://localhost:8787`
5. เข้าสู่ระบบด้วย `phop@super-x.tech` ทางอีเมล หรือบัญชี Lark ที่ผู้ดูแลผูก Open ID ไว้และอยู่ในองค์กรที่อนุญาต
6. เพิ่มพนักงาน โดยระบุรหัสอ้างอิง ชื่อ **อีเมลบริษัท** และฝ่าย
7. เพิ่มข้อสอบตัวอย่าง 3 ฝ่าย ตรวจคำถาม/เฉลย แล้วเปิดให้สอบ
8. พนักงานยืนยันตัวตนผ่านอีเมลหรือ Lark ทำข้อสอบ และผู้ประเมินตรวจข้อเขียนก่อนยืนยันผล

หน้าเข้าสู่ระบบจะแสดงเฉพาะช่องทางที่ตั้งค่าพร้อมแล้ว หากไม่มีคีย์บริการจริง จะเปิดดูหน้าเว็บได้แต่เข้าสู่ระบบไม่ได้ **ไม่มีรหัสทดลองหรือช่องทางข้ามการยืนยันตัวตน**

## ช่องทางที่ 1: อีเมลพร้อมรหัสยืนยัน

ใช้ Resend ส่งอีเมลยืนยันตัวตน:

- ยืนยันโดเมนผู้ส่ง `super-x.tech` ใน Resend ก่อน
- ตั้ง `EMAIL_FROM` ใน `wrangler.jsonc` ให้ตรงกับโดเมนที่ยืนยันแล้ว ค่าเริ่มต้นคือ `SuperX Academy <noreply@super-x.tech>`
- ใส่ `RESEND_API_KEY` และ `SESSION_SECRET` ใน `.dev.vars` สำหรับเครื่องทดลอง หรือ Cloudflare Secrets สำหรับระบบจริง
- กรอกอีเมล → รับรหัส 6 หลัก → ยืนยันภายใน 10 นาที รหัสใช้ได้เพียงครั้งเดียว
- ส่งรหัสเฉพาะอีเมลผู้ประเมินที่อนุญาตหรือพนักงานที่มีรายชื่อและยังไม่ถูกปิดสิทธิ์
- จำกัดการขอรหัสและการลองกรอกผิด ไม่แสดง OTP ในหน้าเว็บหรือประวัติ

ตัวอย่าง `.dev.vars` (แทนค่าด้วยค่าจริง เก็บเฉพาะเครื่องและห้ามขึ้น GitHub):

```dotenv
SESSION_SECRET="random-value-at-least-32-characters"
RESEND_API_KEY="your-resend-api-key"
```

## ช่องทางที่ 2: Lark

การล็อกอิน Lark ต้องใช้ **Custom App** ต่างจาก Custom Bot ที่ใช้แจ้งผลสอบ

1. สร้าง/ตั้งค่าแอปใน Lark Developer Console เปิดความสามารถ Web Login
2. ตั้ง callback URL ให้ตรงกับเว็บจริง เช่น `https://academy.super-x.tech/api/auth/lark/callback`
3. เผยแพร่ Web Login ให้ผู้ใช้ในบริษัท ไม่ใช้ข้อมูลอีเมลติดต่อของ Lark เป็นหลักฐานสิทธิ์เข้าใช้งาน
4. ตั้งค่า `APP_URL`, `LARK_APP_ID`, `LARK_TENANT_KEY` ใน `wrangler.jsonc`
5. เก็บ `LARK_APP_SECRET` เป็น Cloudflare Secret หรือ `.dev.vars` สำหรับเครื่องทดลอง
6. ผูก Open ID ของผู้ประเมินตามตัวอย่างด้านล่าง ส่วนพนักงานให้เพิ่มในหน้า **พนักงาน → อีเมล / Lark** หลังเข้าด้วย OTP
7. เมื่อกดเข้าสู่ระบบ ระบบจะนำไปยืนยันที่ Lark แล้วกลับมาสร้างเซสชันของเว็บ

ตรวจ `tenant_key` ให้ตรงกับองค์กรทุกครั้ง แล้วตรวจ `open_id` กับบัญชีที่ผู้ดูแลผูกไว้ ไม่จับคู่อัตโนมัติด้วยอีเมลติดต่อในโปรไฟล์ Lark เพราะอีเมลดังกล่าวอาจยังไม่ได้ยืนยันเจ้าของกล่องจดหมาย

สำหรับผู้ประเมิน ให้เพิ่ม `LARK_ADMIN_BINDINGS` ใน vars เป็น JSON string เช่น:

```json
"LARK_ADMIN_BINDINGS": "{\"ou_YOUR_REAL_OPEN_ID\":\"phop@super-x.tech\"}"
```

แทน Open ID ด้วยค่าจริงของบัญชีในแอป Lark นี้ ห้ามใช้ชื่อแสดงผลหรือรหัสพนักงานแทน ค่าอีเมลใน mapping ต้องอยู่ใน `ADMIN_EMAILS` ด้วย

## นำขึ้น Cloudflare

```sh
npx wrangler login
npx wrangler secret put SESSION_SECRET
npx wrangler secret put RESEND_API_KEY
# ตั้งเมื่อเปิด Lark Login
npx wrangler secret put LARK_APP_SECRET
npm run deploy
```

`npm run deploy` จะหาฐานข้อมูล D1 `employee-assessments` หรือสร้างให้ถ้ายังไม่มี ใส่ ID ลง `wrangler.jsonc` ทำ migration แล้ว deploy ในคำสั่งเดียว ถ้าเชื่อม repo จากหน้า Cloudflare ให้ตั้ง Deploy command เป็น `npm run deploy`

`SESSION_SECRET` ต้องเป็นค่าสุ่มยาวอย่างน้อย 32 ตัวอักษร ชื่อซับโดเมนเช่น `academy.super-x.tech` เป็นเพียงตัวอย่าง ยังไม่ได้ผูก DNS ให้ ดูขั้นตอนทั้งหมดที่ [docs/DEPLOYMENT-TH.md](docs/DEPLOYMENT-TH.md)

## ความสามารถด้านข้อสอบ

- แยกชุดข้อสอบและสิทธิ์ดูข้อมูลตามฝ่ายและพนักงาน
- ข้อเลือกตอบตรวจฝั่งเซิร์ฟเวอร์ ข้อเขียนมีเกณฑ์/คำสำคัญช่วยผู้ประเมิน และเลือกเปิด Workers AI เพิ่มได้
- ผู้ประเมินยืนยันคะแนนข้อเขียนก่อนสรุปผ่าน/ไม่ผ่าน ใช้อีเมลที่ยืนยันแล้วบันทึกชื่อผู้ประเมิน
- บันทึกคำตอบระหว่างทำ กลับมาทำต่อได้ก่อนหมดเวลา และบังคับ deadline จากเซิร์ฟเวอร์
- ตรวจจำนวนสอบ ป้องกันการกดเริ่ม/ส่งซ้ำ และจำกัดสอบซ่อมที่ 1 ครั้ง
- หน้าภาพรวม รายการผลสอบ ตัวกรอง CSV และแบบฟอร์มสร้างข้อสอบ
- ตัวอย่าง 3 ฝ่ายเป็นฉบับร่าง ต้องให้หัวหน้าฝ่ายตรวจเนื้อหาก่อนเปิดจริง
- เปลี่ยนอีเมล/ปิดสิทธิ์ได้ การเข้าสู่ระบบเดิมถูกยกเลิกทันที โดยไม่ล้างประวัติการสอบ

## แจ้งผลผ่าน Lark Bot

```sh
npx wrangler secret put LARK_WEBHOOK_URL
npx wrangler secret put LARK_SIGNING_SECRET
```

`LARK_SIGNING_SECRET` ใช้เมื่อ Bot เปิดตรวจลายเซ็น ตั้ง `APP_URL` เป็น URL เว็บจริงเพื่อแนบลิงก์ผลสอบ ข้อสอบที่มีข้อเขียนแจ้งสถานะรอประเมินก่อน และส่งผลสุดท้ายหลังตรวจครบ คิว D1 ลองส่งใหม่เมื่อเครือข่ายผิดพลาด มีหน้าติดตามและสั่งลองซ้ำได้

Lark Bot แจ้งผลเข้ากลุ่มผู้ประเมิน ส่วน Lark App ใช้ล็อกอิน เป็นคนละชุดค่าตั้งค่า

## เปิด Workers AI (เลือกใช้)

เพิ่ม `"ai": { "binding": "AI" }` ที่ระดับบนสุดใน `wrangler.jsonc` เปลี่ยน `vars.AI_ENABLED` เป็น `"true"` แล้ว deploy ผู้ประเมินจะกดวิเคราะห์เนื้อหาได้ AI ไม่ให้คะแนนสุดท้ายและไม่ตัดสินการทุจริต ระบบยังทำงานด้วยเกณฑ์ตรวจได้หากไม่เปิด AI

## นำขึ้น GitHub

อัปโหลดไฟล์ภายในโฟลเดอร์นี้เป็นราก repository รวม `.github/` และ `.gitignore` หรือใช้ Git:

```sh
git init -b main
git add .
git commit -m "Add email and Lark employee assessment platform"
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

แทน URL ด้วย repository จริง ห้ามอัปโหลด `.dev.vars`, `.env`, `.wrangler/`, `node_modules/` หรือไฟล์สำรองฐานข้อมูล

Workflow ตรวจโค้ดทำงานเมื่อ push main/เปิด PR ส่วน **Deploy to Cloudflare** ต้องกด Run workflow เอง หลังตั้ง Secrets และ Variables ตามคู่มือ

## อัปเกรดจากรุ่นรหัสเข้าสอบ

ใช้ `npm run db:remote` ก่อน deploy เพื่อทำ migration `0002_email_lark_auth.sql` และ `0003_lark_pkce.sql` ผลสอบเดิมยังอยู่ รหัสเข้าสอบและเซสชันเก่าใช้ไม่ได้แล้ว ให้ผู้ประเมิน `phop@super-x.tech` เข้าผ่านอีเมล/Lark แล้วเพิ่มอีเมลให้พนักงานเดิมในหน้า **พนักงาน → แก้ไขอีเมล** ไม่ต้องสร้างพนักงานใหม่และไม่รีเซ็ตสิทธิ์สอบ

ลบ `ADMIN_PASSWORD` เดิมจาก Cloudflare ได้ เพราะโค้ดไม่ใช้งานค่านี้แล้ว
